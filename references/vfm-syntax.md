## 1. VFMとは

### 1.1 概要

**VFM (Vivliostyle Flavored Markdown)** は、CSS組版エンジン Vivliostyle のために開発されたMarkdown方言である。CommonMark および GFM (GitHub Flavored Markdown) をベースに、出版・組版に必要な以下の拡張を加えている：

- **ルビ**: 日本語出版に不可欠なルビ（ふりがな）を簡潔な記法で記述
- **脚注**: 本文中の参照と脚注内容の関連付け
- **改ページ**: 明示的なページ区切り
- **メタデータ**: タイトル・著者名などの書誌情報の埋め込み

VFM仕様上のMarkdownからHTMLへの変換は、Vivliostyle CLI (`vivliostyle build`) が自動で行う。ユーザはMarkdownを書くだけで、Vivliostyleが内部的にVFM→HTML→CSS組版→PDF/EPUB のパイプラインを実行する。

### 1.2 novel2epub-jp における位置づけ

novel2epub-jp スキルでは、執筆段階から VFM 記法を使用することを推奨する。特にルビ記法 `{漢字|よみ}` は、執筆と同時に付与することで、後工程でのルビ付与作業が不要になる。

```
執筆 (novel2hermes-jp)        組版 (novel2epub-jp)
  │                              │
  │  VFM記法で原稿執筆          │  Vivliostyle CLI が
  │  {漢字|よみ} [^1] ===       │  VFM→HTML 変換を実行
  │                              │
  └──────── novel/*.md ─────────┘
```

### 1.3 対応処理系

| 処理系 | バージョン | 備考 |
|--------|-----------|------|
| Vivliostyle CLI | v11.0.0+ | `vivliostyle build` で自動VFM変換 |
| @vivliostyle/vfm | v2.x | 単体利用可（VFM→HTML変換のみ） |

## 2. ルビ記法

ルビは VFM の最重要拡張である。日本語小説の組版において、漢字の読み仮名を簡潔に記述できる。

### 2.1 基本：単語ルビ

**記法**:
```markdown
{漢字|よみ}
```

**生成HTML**:
```html
<ruby>漢字<rt>よみ</rt></ruby>
```

**組版イメージ**: 漢字の右側（縦書き時）または上側（横書き時）に「よみ」が小さく表示される。

**例**:
```markdown
{灯|あかり}は六つになったばかりだった。
```
→
```html
<ruby>灯<rt>あかり</rt></ruby>は六つになったばかりだった。
```

### 2.2 複数単語連続ルビ

複数の単語に連続してルビを振る場合、それぞれを個別の `{}` で囲む。

**記法**:
```markdown
{智|ち}に{棹|さお}させば{流|なが}される
```

**生成HTML**:
```html
<ruby>智<rt>ち</rt></ruby>に<ruby>棹<rt>さお</rt></ruby>させば<ruby>流<rt>なが</rt></ruby>される
```

**例（小説での固有名詞）**:
```markdown
{九十九|つくも}の{紅|くれない}の目が、{灯|あかり}を見下ろしていた。
```

### 2.3 グループルビ（熟語ルビ）

複数の漢字をまとめて一つのルビとして扱う。パイプ `|` の左側の文字列全体に対して右側の読みが振られる。

**記法**:
```markdown
{日本語|にほんご}
```

**生成HTML**:
```html
<ruby>日本語<rt>にほんご</rt></ruby>
```

**組版上の差異**:

| 記法 | 意味 | ルビの振られ方 |
|------|------|--------------|
| `{日本語\|にほんご}` | グループルビ | 「日本語」全体に「にほんご」 |
| `{日\|に}{本\|ほん}{語\|ご}` | モノルビ | 各文字に個別の読み |

### 2.4 ルビの入れ子（非対応）

VFM はルビの入れ子（ルビの中にさらにルビ）をサポートしない。必要な場合は HTML を直書きする。

```markdown
<!-- 非対応 -->
{親文字{子文字|こよみ}|おやよみ}
```

### 2.5 ルビと句読点

ルビは句読点を含まない。読点「、」や句点「。」はルビの外に置く。

```markdown
<!-- 正しい -->
{灯|あかり}は、{九十九|つくも}を見た。

<!-- 誤り（読点がルビ内に入っている） -->
{灯は、|あかりは}九十九を見た。
```

### 2.6 ルビ内の空白を含む表記

空白を含むテキストにルビを振ることも可能（VFMはパイプ `|` をデリミタとして解釈する）。

```markdown
{焔 緋色|ほむら ひいろ}が刀を構えた。
```

**生成HTML**:
```html
<ruby>焔 緋色<rt>ほむら ひいろ</rt></ruby>が刀を構えた。
```

### 2.7 ルビのエスケープ

本文中で `{漢字|よみ}` という文字列リテラルを表示したい場合（ルビとして解釈させたくない場合）は、バックスラッシュでエスケープする。

```markdown
\{これはルビではない\}
```

## 3. 脚注

### 3.1 基本記法

脚注は本文中の参照マーカーと、文書末尾の脚注定義から構成される。

**本文中の参照**:
```markdown
この山には古くから妖狐が棲むという[^1]。
```

**脚注定義（文書末尾または任意の位置）**:
```markdown
[^1]: 妖狐（ようこ）—— 長年生きた狐が妖力を持ったもの。
```

**生成HTML**:
```html
<p>この山には古くから妖狐が棲むという<a href="#fn1" id="fnref1">[1]</a>。</p>
...
<footer>
  <ol>
    <li id="fn1">妖狐（ようこ）—— 長年生きた狐が妖力を持ったもの。<a href="#fnref1">↩</a></li>
  </ol>
</footer>
```

### 3.2 複数脚注

脚注IDは自動で連番が振られる。識別子には数字以外に任意の文字列も使用可能。

```markdown
夏の盛りを過ぎても蛍が舞うのは、妖気のせいだと言われている[^youki]。

[^youki]: 妖気（ようき）—— 妖が発する霊的な気配。
```

### 3.3 同一脚注の複数箇所からの参照

同じ脚注を複数箇所から参照できる。

```markdown
九十九は百年以上この社に棲み着いている[^tsukumo]。
その力は里の人々にも恐れられていた[^tsukumo]。

[^tsukumo]: 九十九（つくも）—— 本作の主人公である妖狐。神格に近い力を持つ。
```

### 3.4 脚注の改行と段落

脚注定義内では、インデントを揃えることで複数行・複数段落の脚注内容を記述できる。

```markdown
[^1]: 第一段落。
    インデントを揃えることで続けられる。

    空行を入れて第二段落。
```

### 3.5 脚注の組版上の注意

- 脚注はVFM→HTML変換時に対応する `<a>` タグに変換される
- Vivliostyle の CSS (`@vivliostyle/theme-bunko`) では脚注がページ下部に自動配置される
- EPUB 出力 (`@vivliostyle/theme-epub3j`) では章末脚注として扱われる

## 4. 改ページ

### 4.1 水平線による改ページ

3つ以上の `=` による水平線は、**明示的な改ページ**として扱われる。これは VFM の重要な拡張であり、通常の Markdown（`---` や `***` による `<hr>`）とは異なる動作をする。

**記法**:
```markdown
===
```

**生成HTML**:
```html
<hr class="page-break" />
```

Vivliostyle の CSS で `.page-break` に `page-break-after: always` が設定されているため、続くコンテンツは新しいページから始まる。

### 4.2 小説での使用パターン

**章区切り**:
```markdown
九十九はひとり、月明かりの下で嗤った。

===

# 第2章
```

**シーン転換（場面転換）**:
```markdown
灯は茣蓙の上で正座して言った。

===

夕方。渓谷に青白い光が満ちていた。
```

**挿絵の前後**:
```markdown
===

![狐火の夜](image/序章2.webp)

===
```

### 4.3 通常の水平線との区別

| 記法 | 意味 | HTML出力 |
|------|------|----------|
| `===` | 改ページ | `<hr class="page-break" />` |
| `---` | 水平線（区切り線） | `<hr />` |
| `***` | 水平線（装飾区切り） | `<hr />` |

**重要**: 改ページが必要な場面では必ず `===` を使用する。`---` は単なる区切り線であり、ページは改まらない。

## 5. 見出し

### 5.1 基本記法

VFM は CommonMark の ATX 見出し（`#` で始まる行）をサポートする。

```markdown
# 表題（作品タイトル）
## 章見出し
### 節見出し
#### 小見出し
```

### 5.2 小説組版における推奨使い分け

| レベル | 記法 | 用途 | 組版時の典型スタイル |
|--------|------|------|-------------------|
| `#` | `# 妖狐は、嗤う` | **表題**（作品タイトル） | 大サイズ・中央配置・単独ページ |
| `##` | `## 序章 狐火の夜` | **章見出し** | 改ページ＋中央揃え＋柱への章名出力 |
| `###` | `### 一` | **節見出し**（セクション区切り） | やや大きめ・中央 |
| `####` | `#### 1.` | **小見出し** | 通常サイズ・太字 |

### 5.3 見出しと改ページ

`h2`（`##`）には CSS で `page-break-before: always` を設定するのが novel2epub-jp の既定動作である。章の変わり目で自動的に改ページされる。

```css
/* bunko-custom.css の既定設定 */
h2 {
  page-break-before: always;
  string-set: chapter content();
}
```

### 5.4 Setext 見出し（非推奨）

Setext スタイル（`===` や `---` による下線）は VFM でもサポートされるが、改ページ記法 `===` と衝突するため**使用しないこと**。

```markdown
<!-- 非推奨：改ページ記法と区別がつかない -->
見出し
===
```

## 6. 画像

### 6.1 基本記法

```markdown
![代替テキスト](path/to/image.webp)
```

**生成HTML**:
```html
<img src="path/to/image.webp" alt="代替テキスト" />
```

### 6.2 小説での挿絵の埋め込み

novel2epub-jp では、挿絵を以下のように埋め込む：

```markdown
===

![狐火の夜——渓谷を舞う無数の青白い火の玉](image/序章2.webp)

===
```

**ポイント**:
- 前後に `===` を入れて改ページを保証する（挿絵が単独ページになる）
- `alt` テキストは画像が表示されない環境での代替説明として機能する
- 画像パスは `novel/image/` ディレクトリを基準とする（原稿mdからの相対パス）

### 6.3 画像ファイルの推奨仕様

| 項目 | 推奨値 | 備考 |
|------|--------|------|
| フォーマット | WebP | JPEG/PNG も可 |
| 解像度 | 1200×1756px | A6文庫版見開き相当 |
| カラーモード | RGB | CMYK は非対応 |

### 6.4 画像の代替テキスト

`alt` テキストは、アクセシビリティとEPUB仕様準拠のために**必ず記述する**。

```markdown
<!-- 良い例 -->
![序章：狐火に照らされる朽ちた社の全景](image/序章2.webp)

<!-- 悪い例（alt空） -->
![](image/序章2.webp)
```

## 7. メタデータブロック

### 7.1 YAML Frontmatter

VFM は文書先頭の YAML frontmatter をメタデータとして解釈する。`---` で囲まれたブロック内にキーと値のペアを記述する。

```yaml
---
title: 妖狐は、嗤う
author: カガミカミ水鏡
language: ja
date: 2026-05-29
---
```

### 7.2 HTML コメントによるメタデータ

YAML frontmatter の代わりに、HTML コメント形式でもメタデータを記述できる。

```html
<!--
title: 妖狐は、嗤う
author: カガミカミ水鏡
-->
```

### 7.3 使用可能なメタデータキー

| キー | 意味 | 例 |
|------|------|----|
| `title` | 作品タイトル | `妖狐は、嗤う` |
| `author` | 著者名 | `カガミカミ水鏡` |
| `language` | 言語コード | `ja` |
| `date` | 作成年月日 | `2026-05-29` |
| `readingProgression` | ページ送り方向 | `rtl`（右→左） |
| `class` | 本文に付与するCSSクラス | `novel` |

### 7.4 vivliostyle.config.js との関係

メタデータは `vivliostyle.config.js` の設定より優先される。ただし、novel2epub-jp では `vivliostyle.config.js` での一元管理を推奨する。

```js
// vivliostyle.config.js（推奨：一元管理）
module.exports = {
  title: '妖狐は、嗤う',
  author: 'カガミカミ水鏡',
  language: 'ja',
  // ...
};
```

## 8. コードブロック

### 8.1 基本記法

バッククォート3つ（またはチルダ3つ）で囲む。

````markdown
```
ここはコードブロック
複数行にわたる
```
````

### 8.2 言語指定

開始行に言語名を付けると、シンタックスハイライトが適用される（Vivliostyle 組版時には通常CSS装飾として反映）。

````markdown
```python
def hello():
    print("こんにちは")
```
````

### 8.3 小説での用途

小説本文でコードブロックを使うことは稀だが、以下のような特殊なケースで用いる：

- 手紙文や日記の引用（視覚的に区別したい場合）
- 作品中の石碑の碑文や古文書の引用
- 作品の後書きや解説でのサンプルコード表示

```markdown
境内の石碑には、こう刻まれていた。

```
ここに眠るは
名も無き妖の骸
人の子よ 手向けるなかれ
```
```

## 9. 表（テーブル）

### 9.1 基本記法

GFM 互換のパイプテーブル記法。

```markdown
| 名前 | 種族 | 年齢 |
|------|------|------|
| 灯 | 人間 | 6 |
| 九十九 | 妖狐 | 500+ |
| 焔鋼 | 妖 | 300+ |
```

**生成HTML**:
```html
<table>
  <thead>
    <tr><th>名前</th><th>種族</th><th>年齢</th></tr>
  </thead>
  <tbody>
    <tr><td>灯</td><td>人間</td><td>6</td></tr>
    <tr><td>九十九</td><td>妖狐</td><td>500+</td></tr>
    <tr><td>焔鋼</td><td>妖</td><td>300+</td></tr>
  </tbody>
</table>
```

### 9.2 カラムの配置指定

ヘッダ区切り行のコロンでカラムごとの配置を指定できる。

```markdown
| 左寄せ | 中央揃え | 右寄せ |
|:-------|:--------:|-------:|
| 左     | 中央     | 右     |
```

### 9.3 小説での用途

テーブルは主に以下の用途で使われる：

- 登場人物一覧（巻頭または巻末）
- 用語集
- 既刊一覧（シリーズ作品の場合）

```markdown
## 登場人物

| 名前（ふりがな） | 種族 | 備考 |
|------|------|------|
| {灯|あかり} | 人間 | 主人公。6歳の少女。 |
| {九十九|つくも} | 妖狐 | 500年生きた狐の妖。 |
| {焔鋼|ほむら はがね} | 妖 | 妖の里の長。 |
```

### 9.4 縦書き組版でのテーブル

縦書き（`writing-mode: vertical-rl`）の文庫PDFでは、テーブルはブラウザの自動レイアウトに任せるか、`bunko-custom.css` で明示的に横組みに切り替える必要がある場合がある。

```css
/* テーブルを含むページを横書きに戻す（必要に応じて） */
.table-page {
  writing-mode: horizontal-tb;
}
```

## 10. 強調

### 10.1 イタリック（斜体）

```markdown
*イタリック* または _イタリック_
```

**生成HTML**: `<em>イタリック</em>`

**小説での用途**: 心内語（内心の独白）、外国語の単語、強調表現。

```markdown
——*この子は、喰えない*——

九十九は心の中でそう呟いた。
```

### 10.2 ボールド（太字）

```markdown
**ボールド** または __ボールド__
```

**生成HTML**: `<strong>ボールド</strong>`

**小説での用途**: 強い強調、警告、固有名詞の強調。

```markdown
「**喰うのは、明日でよい**」

九十九はそう言い聞かせるように呟いた。
```

### 10.3 打ち消し線

```markdown
~~打ち消し線~~
```

**生成HTML**: `<s>打ち消し線</s>`

**小説での用途**: 誤って口にした言葉の訂正、削除されたテキストの表現。

```markdown
「私はおまえを~~喰う~~……いや、なんでもない」
```

### 10.4 イタリック＋ボールド

```markdown
***イタリック＋ボールド***
```

**生成HTML**: `<em><strong>イタリック＋ボールド</strong></em>`

### 10.5 縦書き組版での注意

- イタリックは和文フォントでは疑似斜体になる（游明朝など多くの和文フォントはイタリック体を持たない）
- 縦書きではイタリック・ボールドともに視認性が落ちる場合がある
- 強調が必要な場合は、圏点（傍点）の代替として `<em class="emphasis-dot">` を直書きする選択肢もある（§15.1 参照）

## 11. リンク

### 11.1 基本記法

```markdown
[リンクテキスト](https://example.com)
```

**生成HTML**: `<a href="https://example.com">リンクテキスト</a>`

### 11.2 タイトル属性付き

```markdown
[リンクテキスト](https://example.com "タイトル")
```

### 11.3 参照スタイル

```markdown
本文中の[リンク][ref1]はこう書く。

[ref1]: https://example.com "タイトル"
```

### 11.4 小説でのリンク使用

電子書籍（EPUB）では、リンクは以下の用途で使われる：

- 目次から各章への内部リンク（Vivliostyle が `toc: true` で自動生成）
- 奥付・著者Webサイトへのリンク
- 脚注の自動リンク（VFM が自動変換）

```markdown
## 奥付

著者: カガミカミ水鏡
Web: [著者サイト](https://example.com)
Twitter: [@author](https://twitter.com/author)
```

PDF 出力では、`@vivliostyle/theme-bunko` がリンクを装飾（色・下線など）する。印刷を前提とする場合はテキストとしてURLを併記することを推奨。

## 12. 引用

### 12.1 基本記法

```markdown
> これは引用文です。
> 複数行にわたって書けます。
```

**生成HTML**:
```html
<blockquote>
  <p>これは引用文です。複数行にわたって書けます。</p>
</blockquote>
```

### 12.2 入れ子の引用

```markdown
> 外側の引用
>
> > 内側の引用
```

### 12.3 小説での用途

引用は以下のような場面で使われる：

- 作中作の引用（登場人物が読んでいる本の一節）
- 石碑・古文書の引用
- 手紙の引用
- 章の冒頭に置くエピグラフ（引用句）

**エピグラフの例**:
```markdown
> 狐の嫁入りを見た者は、二度と里に帰れぬという。
> ——古老の言い伝え

===

# 序章 狐火の夜
```

### 12.4 縦書きでの引用スタイル

`bunko-custom.css` で引用ブロックのインデントや左罫線を設定することで、縦書きでも視覚的に区別できる。

```css
blockquote {
  margin-inline-start: 2em;
  margin-inline-end: 1em;
  border-inline-start: 2px solid #333;
  padding-inline-start: 1em;
}
```

## 14. 小説向け実践的な使用パターン

### 14.1 典型的な章の構成

以下は、novel2epub-jp が想定する典型的なMarkdown原稿の章構成である。

```markdown
<!--
title: 妖狐は、嗤う
author: カガミカミ水鏡
language: ja
-->

# 妖狐は、嗤う

> 狐の嫁入りを見た者は、二度と里に帰れぬという。

===

## 序章 狐火の夜

### 一

蝉が啼いていた。

夏の終わりの湿った空気が山肌を這い、渓谷のそこかしこに夕闇を溜めていた。

{灯|あかり}は六つになったばかりだった。藍染めの着物の袖は長すぎて二重に折り返してあり、赤い帯だけが暮れなずむ山の中でひときわ鮮やかに浮かんでいた。

——そのときだった。

空気が、ふわりと冷えた。

{九十九|つくも}が闇の中から歩み出てきた。黒い着物。目——ぬれた{紅|くれない}の目が、{灯|あかり}を見下ろしていた。

「おまえ、ひとりか」

声は低く、耳の奥に残るような響きだった。

{灯|あかり}は泣きやんだ。*怖いとは思わなかった*。

「おねえちゃん」

{灯|あかり}は立ち上がり、女の顔をじっと見上げた。

「おねえちゃん、おうちはどこ？」

九十九の口元が、ほんのわずかに歪んだ。嗤っているのか、笑っているのか。

「……退屈しのぎだ。ついて来い」

===

### 二

朽ちた社だった。

山の尾根に抱かれるように建つ古社[^1]の境内には、天を衝くような杉が一本立っていた。

{九十九|つくも}は杉の根元に茣蓙を敷き、{灯|あかり}を座らせた。

「ここで寝ろ」

「あかり、おなかすいちゃった」

九十九は境内の隅に生えた木から、赤黒い果実をもいで差し出した。

{灯|あかり}はためらわずにかぶりつき、果汁を顎に垂らしながら笑った。

「あまい！」

===

![狐火に照らされる朽ちた社](image/序章2.webp)

===

[^1]: 古社（こしゃ）—— 古い神社。この社は数百年にわたり打ち捨てられ、本来の祭神も忘れ去られている。
```

### 14.2 地の文と会話の書き分け

VFM（Markdown）では、**空行**が段落区切りとなる。これを利用して、地の文と会話を自然に書き分ける。

```markdown
{灯|あかり}は袖を握りしめて泣いた。涙がぱたぱたと膝の上の草履に落ちて、乾いた藁に吸い込まれていった。

——そのときだった。

空気が、ふわりと冷えた。

「おまえ、ひとりか」

声は低く、耳の奥に残るような響きだった。

{灯|あかり}は顔を上げた。
```

**ポイント**:
- 会話文の前後は空行を入れる（読みやすさと、VFMパーサへの負荷軽減のため）
- 会話の「」の中にルビは不要（台詞は読みのまま）
- 地の文に登場する漢字にはルビを振る

### 14.3 ルビを多用する場面

固有名詞や難読漢字の**初出時**には必ずルビを振る。2回目以降は読者の習熟に任せて省略可（作品の文体方針に従う）。

```markdown
{九十九|つくも}が右手をひらりと振った。

その指先から、青白い光が滲み出た。九十九は、{無数|むすう}の{狐火|きつねび}を{自在|じざい}に{操|あやつ}ることができるのだった。
```

**ルビ付与の基準（novel2epub-jp推奨）**:

| 対象 | ルビ | 理由 |
|------|------|------|
| 固有名詞（初出） | 必須 | 読者が登場人物名を覚える補助 |
| 難読漢字 | 初出時必須 | 読了の妨げを防ぐ |
| 当て字・特殊な読み | 毎回 | 誤読防止 |
| 一般的な漢字 | 不要 | 過剰なルビは可読性を下げる |

### 14.4 挿絵を含む章の構成

```markdown
## 第1章 鋼の目覚め

### 一

{焔鋼|ほむら はがね}は、妖の里の長だった。

（本文……）

===

![鋼の背に刻まれた無数の傷跡](image/一章1.webp)

===

### 二

「おまえ、まだあの童のことを」

{焔緋色|ほむら ひいろ}が言った。

（本文……）
```

### 14.5 複数章をまたぐ脚注の扱い

novel2epub-jp のビルドでは、全原稿ファイルを結合して1つの文書として扱う。脚注IDはファイルをまたいで一意である必要がある。

```markdown
<!-- 序章-01.md -->
[^tsukumo]: 九十九（つくも）—— 500年生きた狐の妖。

<!-- 第1章-01.md -->
<!-- 同じ [^tsukumo] を参照できる -->
{焔鋼|ほむら はがね}は{九十九|つくも}の名を聞いて眉をひそめた[^tsukumo]。
```

**注意**: 脚注IDの重複定義はエラーの原因となる。脚注定義は初出のファイルにのみ記述する。

### 14.6 メタデータの運用パターン

novel2epub-jp では、メタデータは `vivliostyle.config.js` に一元化し、個別の原稿ファイルには原則として書かない。

```markdown
<!-- 非推奨：各ファイルに frontmatter を書く -->
---
title: 妖狐は、嗤う
author: カガミカミ水鏡
---
```

代わりに：

```js
// vivliostyle.config.js（推奨）
module.exports = {
  title: '妖狐は、嗤う',
  author: 'カガミカミ水鏡',
  language: 'ja',
  // ...
};
```

## 15. VFM未対応の日本語組版要素と代替方法

VFMは出版向けに拡張されているが、日本語組版で求められるすべての要素をカバーしているわけではない。以下に、未対応要素とその代替方法をまとめる。

### 15.1 圏点（傍点・脇点）

**状況**: VFM は圏点（文字の横に付ける強調の黒丸など）の記法を提供していない。

**代替方法**: HTML 直書き + CSS で対応する。

```markdown
<!-- HTML直書き -->
<em class="emphasis-dot">この言葉を強調したい</em>
```

```css
/* bunko-custom.css に追加 */
em.emphasis-dot {
  font-style: normal;
  text-emphasis: filled circle;
  -webkit-text-emphasis: filled circle;
}
```

**圏点の種類（CSS `text-emphasis-style`）**:

| 値 | 表示 | 用途 |
|----|------|------|
| `filled circle` | ● | 一般的な圏点 |
| `open circle` | ○ | 白丸圏点 |
| `filled dot` | • | 小さな圏点 |
| `filled sesame` | ﹅ | ゴマ圏点（芝麻点） |
| `open sesame` | ﹆ | 白ゴマ圏点 |
| `double circle` | ◉ | 二重丸 |
| `triangle` | ▲ | 三角圏点 |

**実践例**:
```markdown
灯は<em class="emphasis-dot">ただ、ひとりで</em>歩き出した。
```

### 15.2 割注

**状況**: 割注（行内に小さく2行で挿入する注釈）は VFM 未対応。

**代替方法A**: CSS の `inline` レイアウトで再現する。

```markdown
<!-- HTML直書き -->
<span class="warichu">この部分が割注です</span>
```

```css
span.warichu {
  display: inline-block;
  font-size: 0.6em;
  line-height: 1.2;
  writing-mode: horizontal-tb; /* 縦書き本文中でも横書きにする場合 */
}
```

**代替方法B**: 脚注で代用する。割注が必要な箇所に脚注番号を振り、内容は脚注としてページ下部に配置する。これは組版的に最も安定した方法である。

```markdown
古社[^kosha]の境内には、天を衝くような杉が立っていた。

[^kosha]: 古社（こしゃ）—— 古い神社。すでに祭神は忘れ去られている。
```

### 15.3 縦中横（縦書き中の横組み数字）

**状況**: 縦書き文中で2桁以上の数字を横に並べる「縦中横」は VFM 未対応。

**代替方法**: CSS の `text-combine-upright` プロパティを使用する。

```markdown
<!-- HTML直書き -->
<span class="tate-chu-yoko">10</span>年前の出来事だった。
```

```css
span.tate-chu-yoko {
  text-combine-upright: all;
}
```

**注意**: `text-combine-upright: all` は最大で3桁程度の数字に有効。4桁以上の場合は CSS の `digits` 値を使う（ブラウザ対応が限られる）。

```css
/* 4桁の縦中横 */
span.tate-chu-yoko-4 {
  text-combine-upright: digits 4;
}
```

### 15.4 段組（2段組・3段組）

**状況**: 段組は VFM ではなく CSS の管轄。

**代替方法**: `bunko-custom.css` で `column` プロパティを設定する。

```css
.two-columns {
  column-count: 2;
  column-gap: 2em;
  writing-mode: horizontal-tb; /* 段組は横書きで */
}
```

### 15.5 禁則処理とぶら下げ

**状況**: 日本語の禁則処理（行頭禁則文字・行末禁則文字の制御）およびぶら下げは VFM ではなく CSS / Vivliostyle の組版機能に依存する。

**対応**: Vivliostyle はデフォルトで日本語禁則処理をサポートしている。`@vivliostyle/theme-bunko` も適切な禁則設定を持っているため、特に対応不要。

### 15.6 総ルビ（総振り仮名）

**状況**: すべての漢字にルビを振る「総ルビ」は、VFM のルビ記法を全漢字に適用することで実現する。手動で全漢字に `{}` を付けるのは現実的でない。

**代替方法**: `scripts/ruby-dict.py` による自動ルビ付与。

```bash
python3 scripts/ruby-dict.py --project /mnt/y/novel/yoko-project/ --mode all-kanji
```

または、VFM 自体には自動ルビ機能がないため、原稿執筆時に `{漢字|よみ}` を逐次付与する。

## 16. 補足：CommonMark / GFM との関係

### 16.1 継承している機能

VFM は以下の CommonMark / GFM 機能を完全に継承している：

| 機能 | 記法 | 備考 |
|------|------|------|
| 段落 | 空行区切り | |
| 見出し | `#` ATX / Setext | Setext は非推奨（`===` と衝突） |
| 強調 | `*italic*` `**bold**` | |
| リンク | `[text](url)` | |
| 画像 | `![alt](url)` | |
| コードブロック | ` ``` ` | 言語指定可 |
| インラインコード | `` `code` `` | |
| リスト | `-` `*` `1.` | |
| 引用 | `>` | |
| テーブル | パイプテーブル | GFM 由来 |
| 打ち消し線 | `~~text~~` | GFM 由来 |
| タスクリスト | `- [ ]` `- [x]` | GFM 由来 |
| 自動リンク | `<URL>` | |
| HTML 直書き | `<tag>` | 有効 |

### 16.2 VFM 独自の拡張

| 機能 | 記法 | 用途 |
|------|------|------|
| ルビ | `{漢字\|よみ}` | 日本語出版に必須 |
| 改ページ | `===` | 明示的ページ区切り |
| 脚注 | `[^1]` / `[^1]:` | 脚注の参照と定義 |
| メタデータ | YAML frontmatter / HTMLコメント | 書誌情報の埋め込み |

### 16.3 VFM で非対応の主な機能

| 機能 | 状況 | 代替 |
|------|------|------|
| 圏点（傍点） | 非対応 | HTML + CSS (§15.1) |
| 割注 | 非対応 | CSS または脚注代替 (§15.2) |
| 縦中横 | 非対応 | CSS `text-combine-upright` (§15.3) |
| ルビの入れ子 | 非対応 | HTML 直書き |
| 改段（段区切り） | 非対応 | CSS `column-break` |
| 数式（Math） | 非対応 | HTML + MathML 直書き |
| 目次自動生成 | 非対応 | `vivliostyle.config.js` の `toc: true` |
| 索引 | 非対応 | 手動または Vivliostyle のCSSカウンタ |
